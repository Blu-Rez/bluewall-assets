## خلاصه برای وینگلس
- **S3 (قلعه)** همین چت الان می‌ره. **S4 (شهر + مپ)** و **S6 (زرادخانه + منجنیق دفاعی)** دو چت جدا و موازی هستن؛ چون هر کدوم فایل‌های خودش رو داره و فایل‌های مشترک فقط با چند خط علامت‌دار (`// TR2-S4:` …) عوض می‌شن، مادر می‌تونه پچ‌ها رو یکی‌یکی بی‌دردسر ادغام کنه.
- **S4 رو می‌شه تو ۱ چت بدی یا ۲ چت:** (الف) S4a خونه‌ها+مدنی و S4b تولیدی/معدن/مزرعه · (ب) S4c طبیعت/چراغ/پراپ و S4d حیوون/مردم. جدول زیر مرز فایل‌ها رو مشخص کرده.
- **S5 (چیدمان آزاد)** دو تیکه: S5a (فقط فایل‌های جدید: داده، قانون معتبر بودن، تست، سرور-اسپک) هر وقت؛ S5b (وصل‌کردن به برنامه‌ریزها) فقط بعد از ادغام S3 و S4.
- ترتیب ادغام: **S3 → S4 (هر زیرمرحله به ترتیب رسیدن) → S6 → S5b → S7**. S5a و S6 به S4 وابسته نیستن، فقط ادغامشون بعد از S4 می‌افته.
- قانون فریم (۱۵۰ draw call تو نمای قهرمان) برای هر مرحله پایین‌تر هست.

## 2. The shared pieces every stage uses (exist since S2 — do not fork them)
- `tiers.js`: `LEVEL_CAP`, `TIER_TABLE`, `tierState(level)`, `pieceTier(level, slot)`, `singleTier`, `tiersNeeded`, legacy 6-tier helpers. Raw-node tests import structure modules unbundled → **tiers.js stays import-free**.
- `tr2lib.js`: `tr2.init / load / parts / bake(B, spec, matrix, {bid})` (destructible: walls, towers, houses, gates) · `tr2.instances(parent, spec, matrices, {chunk})` (trees, rocks, lamps, props: **never** for destructible things) · `ensureLevel` + `drop` (lazy tiers). **ONE shared material config** → +0 programs when baked (batched path), +1 when instanced; never add a material type per model.
- Destruct rule: a destructible piece carries `aB` = its battle-target id (`ctx.tgt` returns it; `B.bid(id)` / `bake(..., {bid})`); `patchDestruct(material)` must be called for every Tripo material that carries such pieces (S3's `castle_tr2.js` is the reference: record pieces at build, bake per level into its own Batcher meshes named `static-tr2-*`, patch the new materials, `ctx.rings.rescan()`, then `tr2.drop(old)`). Targets, footprints, nav solids stay exactly as they are unless a stage says otherwise: `noRoute` 667 (limit 700).
- Models: `web/assets/tr2/<key>.glb` at **512 px** (`tools/tr2_retex.mjs IN OUT 512`; 1K only for a hero piece: keep, civic hall), only keys the game uses, `swap.json` gets the key's `ry`; report added MB.

## 3. Frame budget — the owner's rule: every stage keeps the hero view ≤ 150 draw calls
Numbers today (software GL, **not a phone**): strategic cameras `SKIPINTRO=1 python3 dev/p38_perf.py perf 30` = **506 calls / 3.46 M tris** (top view) · hero view after RP1B (castle gate) = 271 calls / 1.44 M tris; RP1C is the chat that cuts the rest (target ≤ 150 / ≤ 400 k). So each TR2 stage must show, at **three hero views (castle gate, open fields, outer mill) and the five strategic cameras**:
1. **Your own cost, measured:** `calls` and `tris` with your group visible vs hidden (`dev/tr2_budget.py`, published with the S3 push: counts frustum-visible draws per mesh-name group).
2. **Net rule:** replacing an old model must not add calls: `calls_after ≤ calls_before` at every view; absolute total ≤ 150 in the hero view once RP1B/RP1C are merged (until then: delta ≤ 0 and the total reported, with the part that is not yours named).
3. **How:** one draw per *texture × chunk*. Bake destructible pieces per texture (castle: ≈ 5 files per tier, 10 in a half/half zone); chunk only when it pays for culling (> 60 k tris of one texture spread over > 150 m) with 64-100 m cells; instanced packs = one call per (node × 48 m cell) at most; far/small things at 256 px; no per-model material; no lights; no new shadow casters beyond what the old model had.
4. Tris: strategic cameras within **+5 %** of the p45 baseline; programs +0…2; resident textures ≤ 120 MB estimate (1K = 5.3 MB, 512 = 1.33, 256 = 0.33 with mips).
5. Each push says which of the five numbers is NOT proven (phone fps, compile time, GPU memory).
