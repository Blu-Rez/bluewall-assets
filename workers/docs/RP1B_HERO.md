## Job 1 — frame drop (first; the owner felt it)
1. Find where the frame time goes in hero mode (sandbox = software GL: absolute fps mean nothing; use **relative** numbers: `renderer.info.render.calls/triangles`, JS ms per frame of `world.update` / hud / crowds / sun-shadow refresh / composer passes, number of shadow casters, pixel ratio). Write the table: before.
2. Cut it with things the player will not miss while walking (write each one down with its before/after): lower pixel-ratio cap in hero mode; shadows only near the hero (smaller shadow box / fewer casters / lower refresh), no bloom/composer extra passes; far-away items hidden or frozen beyond a radius (carts, people, birds, fish, flames, waterfalls, far hamlets), animation updates skipped out of view, far instanced props culled, fog distance shortened so the far world is not drawn; world.update at a lower cadence when the hero is the camera; no new shader programs (+0).
3. **Quality governor (owner-only overlay shows the step):** measure real frame time on the device; if the 1-second average is worse than ~30 fps for 2 s → go one step down (steps: pixel ratio → shadows → far-cull radius → crowd freeze); never go up and down every second (hysteresis, ≥ 8 s before trying a step up). Persist nothing.
4. Target in the hero view at the castle gate and on the open fields: **≤ 150 draw calls and ≤ 400 k triangles** on screen after the diet (the same limit as the underworld). If you cannot reach it, say exactly what remains and why.
5. Gate off = nothing changes (+0 programs, +0 boot bytes, strategic view identical).

## Job 3 — buildings are used by walking to them (the new feature)
Design: in hero mode, when she stands within ≈ 2.5 m of the **nearest face** of any building / worksite / lot / civic building / the keep, a round icon button (a door-knocker or door icon; no words; same glass+turquoise style as the other hero buttons) appears above the action buttons. Tap → she turns to face the building, plays `talk` (or `bow`; if neither looks right, none), and **the same panel the strategic view opens for that building** (the T1 building sheet: barracks → troop row + Train, forge, cottage, mine → rates + Collect, fishery/farm/granary → collect food, Upgrade / Info) opens over the hero view. Its buttons must work exactly as in the strategic view (same code path, no copy). Closing the panel returns to walking. Walk away → the button disappears. Several buildings in range → the nearest one.
- Use the existing registries for «what is this building and what does it open»: how `main.js onTap` / `ctx.pick` resolves a tap to a building id (`ws:<id>`, town lot ids, castle parts, keep) and how it opens the sheet (`bsheet.js` / `upgradeui.js` / `armyui.js`). **Call that same function with the id**; do not duplicate logic. It must keep working when TR2 swaps the models and the owner moves buildings (position/footprint come from the game's own data at call time, never cached constants).
- The hero UI hides all other DOM (`.rp-on …`): make a narrow, explicit exception for the sheet (and its confirm dialogs/toasts) and restore afterwards. The sheet must be usable on a phone at 390 px width with the joystick hidden while it is open.
- What the panel offers is whatever T1 already offers (some buttons are honest placeholders «soon»); **do not add game rules, costs or server calls.** If a building has no panel yet, no button.
- The keep: the existing turquoise door stays; the keep's own sheet also opens by the same button when she is at the keep's other faces.
- Small: a soft glow ring on the ground at the door side of buildings in range is optional (cheap, no new lights).
