## How a yard moves (storeyards.js) — default = +0 draw calls
ST1 draws the nine yards into the static batch `ctx.B` and ONE Tripo atlas bake. With **nothing moved nothing changes: the same batch, the same bake (+0 calls, +0 programs)**. The code remembers, per storehouse, which vertex range of each merged static mesh and of the atlas mesh is its own (per-material counts before / after `buildYard`, the same accounting `bakeTr2` uses). When the player moves a yard:
1. its default picture is **put away** the way `a1_rings.js` puts a wall ring away: the positions of that range are collapsed to 0 (a saved copy, only the range uploaded with `addUpdateRange`); shadows go with it (the depth material reads the same positions);
2. it is **drawn again at the new place** (`buildYard`, same code, same looks, heap fill still follows the skin shader) into a small group of its own: one `Batcher` + one Tripo bake of its own pieces, cached by pose; the live layer runs this as steps, one per frame (`rebuildSteps()`);
3. its **two door lamps are not drawn twice**: the lamp posts are baked again at the new place (the Tripo post from `tr2_s4c`, same code path as `ctx.torch`), the flame sprite and the glow pool they took in the world's lists are moved in place (`flames.p` + the points attribute, `pools.items` + the quad corners);
4. back at the default place → the range is shown again, the lamps go home, the group is dropped. Reset all = the default picture, triangle for triangle (2 077 579 = 2 077 579 in the measurement below).
