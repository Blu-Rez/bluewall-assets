## Pitfalls hit in MERGE-4 (save yourself the time)
1. `applypatch.sh` of several U patches that touch the same shared files leaves `.rej` files that later patches overwrite: apply ONE at a time, hand-merge, delete `.rej`. Hotspots: `bunits.js` (import + `Object.assign(TYPE …)`), `bunits_ground.js`, `bunits_fly.js`, `portraits.js` / `squadicon.js` (do per-key replacement: `portraits.js` lines are 5–11 KB each — **never `grep`/`cat` them without `cut -c1-200`**, same for `unitdefs.json`, a single huge line).
2. A browser battle proof in software GL: page load 3–6 min + ~2 min per screenshot. `dev/m43_units.py TAG [q]` with env `UNITS=ogre,…` and `ARMY='{…}'` limits it (phases: idle ×2 widths → move → attack → death); a 2-unit run is ~35 min. One browser job at a time. After killing a run `kill -9` leftover `headless_shell`. `pkill -f` kills your own shell: use `ps -eo pid,cmd | awk` + `kill`.
3. `getBounds` of gltf-transform is wrong for quantized / skinned meshes: measure in the browser (`Box3.setFromObject(scene, true)`, `dev/m43_ogre_look.js` prints it). The old ogre.glb is in `web/assets` but nothing loads it any more (no fallback if `u2_ogre.glb` is missing → no ogre is drawn; it ships in p43).
4. The dev game boots at forge level 30 = tier 5 (crystal): every unit looks pale / icy in battle shots. Colours of the real model are in the lab shots (`dev/m43_ogre_look.html?tier=0`, `work/m43/ogre_lab_*.png`).
5. `dev/pf_battle_progs.py` got an `ARMY` env (fight with a chosen army); without it the attack is measured with the default army, which has none of the new kinds.
6. Uploaded files get a hash prefix (`4c8dc833-name`): `mv` before `tar`.
7. `u5_fetch_*.sh` in `dev/` read `SF_TOKEN` from the environment (no literal token) but handle credentials and ssh keys: they are NOT in `dev_tests_p43`; keep it so.
8. The Behemoth clip: "Punch" 3.7 s = crouch (0.4 s) → jump (0.9 s) → club raised (1.5 s) → slam ≈ 1.95 s → recovery. `atkOff 1.55`, `atkSp 1.6` start with the club raised and land the slam at the sim's hit time (0.25 s); the swing is cut at `atkDur` 0.8 s by the view (back to the held stance).
