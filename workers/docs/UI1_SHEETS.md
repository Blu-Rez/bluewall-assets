## Job 1 — three looks (the owner picks one)
Read `bsheet.js` (spec registry: which rows/buttons each building kind shows), run the real sheet for 4 kinds on the real game via the gate rig (a barracks with training, a farm/production with Collect, the vault, a wall/tower for the upgrade case) and shoot the **current** state at 390 px as the «before». Then design **three** different directions, each a coherent system (header with the building's portrait/icon + level badge, stat rows with icons and bars, the cost chips, the primary button, the secondary info, locked/disabled states, the queue/progress, the Collect moment):
- **A «Royal glass»** — dark-blue glass plate, gold hairlines, big level crest, ornaments in the Persian/Sasanian flavour of the game (geometric borders, not copied artwork);
- **B «Clean modern»** — calm dark cards, strong typographic hierarchy, large thumbnail, one bright accent per building family;
- **C «Parchment & metal»** — the castle-builder feel (warm stone/leather/brass), embossed buttons.
Draw icons as inline SVG (resource icons, upgrade arrow, train, clock, shield, heart, sword…; one consistent stroke weight) — a small icon set you can reuse everywhere; the building portrait = the game's own thumbnail if one exists, else a procedural emblem per family (do not render a 3D model for this round). Fonts: system stack only (no web fonts, no new requests). Ask: «کدوم؟ A / B / C (یا ترکیب: مثلاً A با دکمه‌های C)». Default = the one you believe is best for a thumb on a phone; say which.
